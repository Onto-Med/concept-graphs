# RAG prompt profiles

RAG prompt profiles live in:

```text
conf/rag/localization/<profile>.yml
```

`src/rag/prompts.py` resolves profiles by normalized language/profile name, falling back to built-in English/German templates. Profiles contain a `template` and `input_variables`; request config can still use the older inline `templates`/`input_variables` shape or a direct `template` override.[^rag-prompts]

# Query-expansion domain prompt profiles

Query-expansion prompt profiles and semantic ontologies live in:

```text
conf/query-expansion/profiles/<profile>.yml
conf/query-expansion/ontologies/<ontology>.yml
# examples: profiles/medical_en.yml, profiles/medical_de.yml, ontologies/medical.yml
```

`src/query_expansion/prompts.py` loads the requested profile from `conf/query-expansion/profiles/` or the `medical_en` fallback, merges a referenced `ontology: <id>` from `conf/query-expansion/ontologies/`, and formats the generation prompt with `{term}`, `{language}`, `{language_name}`, `{limit_per_category}`, `{categories_json}`, `{relations_json}`, and `{schema_instruction}`. Built-in profile names include `medical_en` and `medical_de`; profile inputs are normalized so `medical de`, `medical-de`, and `medical_de` all resolve to `medical_de`, while bare language names such as `de` do not imply a medical profile. Ontologies define stable semantic category IDs, default category IDs, relation IDs/source-target category constraints, and default relation IDs. Profiles keep prompt/profile-specific and localized material: `language_name`, `schema_instruction`, `prompt_template`, `category_labels`, `category_descriptions`, `relation_labels`, and `relation_descriptions`. Profile templates support `{term}` (input term), `{language}` (request language code), `{language_name}` (profile language name), `{limit_per_category}` (requested per-category candidate limit), `{categories_json}` (generated by `prompts.py` from effective request categories plus profile `category_descriptions` as a JSON object keyed by stable category IDs), `{relations_json}` (generated by `prompts.py` from effective relation IDs plus ontology `relations` and profile `relation_descriptions` as JSON objects with `id`, `source_categories`, `target_categories`, and `description`), and `{schema_instruction}` (required JSON output-shape instruction); label/description maps are keyed by stable ontology IDs. IDs remain stable payload values. `src/query_expansion/categories.py` and `src/query_expansion/relations.py` remain built-in medical fallback/helper data for profiles without ontology/category/relation metadata. Requests may override the full template or descriptions for selected categories; relation definitions come from the request or selected ontology/default mini-ontology and are injected through `{relations_json}` with localized profile descriptions. README.md contains the user-facing schema/example for adding new query-expansion ontologies and profiles. API-side profile metadata is exposed via `GET /query-expansion/profiles` and `GET /query-expansion/profiles/{profile_name}` for remote GUI/client use and includes applicable backend-neutral relation metadata plus filtered default relation IDs for client-side validation/intersection, not downstream retrieval strategies.[^qe-prompts]

# Docker/runtime note

Production Docker usage should mount individual prompt profile files or profile directories into the matching `conf/` subdirectory rather than bind-mounting the whole project over `/rest_api`.[^readme]
